# Documentation

The documentation is organized by purpose:

- [architecture.md](architecture.md) describes the current system architecture,
  and should always be up to date with the current implementation.
- `design/` contains design proposals and records of past decisions. These
  documents describe designs at a point in time and may not reflect the current
  system. Each should state its status and link to any document that supersedes
  it.
- [user-guide/](user-guide/) contains end-user documentation.

Implementation details are documented in the `README.md` files of individual
modules, which should also always be up to date with current implementation.
